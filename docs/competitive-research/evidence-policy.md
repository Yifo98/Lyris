# 证据策略

## 可接受证据

| 级别 | 形式 | 可以证明 | 不能证明 |
| --- | --- | --- | --- |
| A | 本机操作记录、公开 AppleScript 字典、可重复命令 | 当前机器与当前版本的实际行为 | 所有版本、所有账号和所有网络环境 |
| B | 固定 commit 的源码链接 | 该提交的实现、模型和许可证 | 闭源主程序内部实现或未来版本 |
| C | 官方产品/平台文档 | 文档明确声明的规则 | 未写明的内部机制 |
| D | 明确标注的推断 | 下一步验证假设 | 产品事实或发布承诺 |

## 记录要求

1. 写访问日期；源码引用固定 commit，不引用漂移的 `main` 行号。
2. 把“观察到”与“推断为”分开。
3. 真实账号测试不记录 Client ID、Secret、Token、Cookie、回调 code、用户名、正在播放记录或完整请求头。
4. 截图先做隐私检查；本研究的截图目录默认不进入 Git。
5. 测试第三方应用只使用 UI 和公开文档，不逆向二进制、不抓取私有 API、不绕过登录/付费/授权。
6. 尚未执行的场景必须写“待验证”，不能用源码 Harness 代替实机结论。

## 失败也属于证据

权限被拒、应用未安装、当前版本无入口或工具不可用时，应记录具体边界和下一次最低风险验证方法，而不是补写猜测。
