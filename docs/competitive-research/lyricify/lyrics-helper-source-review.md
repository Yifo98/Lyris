- README 在该提交仍标记 Spotify 搜索“暂不支持”（[README L23-L30](https://github.com/WXRIW/Lyricify-Lyrics-Helper/blob/983709b2519f7c5ba32206424896533d14159c97/README.md#L23-L30)），但源码存在 `SpotifySearcher`（[SpotifySearcher.cs L7-L48](https://github.com/WXRIW/Lyricify-Lyrics-Helper/blob/983709b2519f7c5ba32206424896533d14159c97/Lyricify.Lyrics.Helper/Searchers/SpotifySearcher.cs#L7-L48)）。这只证明文档与源码漂移，不能证明该搜索器运行可靠。
- 本审阅没有发现可据此证明 parser/generator 往返无损、全格式覆盖、信息行零误判或 Explicit 恢复正确率的实测证据；这些均保持“待验证”。

## 对 Lyris 可安全吸收的抽象

- `LyricDocument` 分开表达文档元数据、行、token、翻译、背景声部和来源。
- parser 与 generator 使用显式格式能力表；未支持的自动识别必须失败可见。
- matcher 使用标题、艺人、专辑、时长与版本冲突，但 Lyris 自行定义权重和测试样本。
- offset 的符号、是否递归背景行、负时间裁剪策略必须由 Lyris 自己明确定义。
- 信息行与 Explicit 处理只能是可撤销、可关闭的启发式步骤，不能覆盖用户原文。
